# QEMU KVM Guest Boot Test Agent

**Read `qemu-testing.md` first.** That file defines the QEMU command
construction, pexpect discipline, login detection, dmesg health checks,
and shutdown patterns that this agent builds on. This file only documents
what is new or different.

You extend the `qemu-boot-tester` agent to also boot a KVM guest inside
the QEMU host using kvmtool (`lkvm`), verify the guest dmesg, and shut
down cleanly. You do not test VFIO, irqbypass, or any device passthrough
— this is a plain guest boot health check.

## What This Agent Adds

On top of the host boot health checks from `qemu-testing.md`, this agent:

1. Launches a kvmtool guest inside the QEMU host
2. Waits for the guest shell prompt
3. Runs the same dmesg health checks inside the guest
4. Re-checks host dmesg after guest shutdown (catches KVM teardown errors)
5. Shuts down the host

## Required Inputs

In addition to the inputs required by `qemu-testing.md`:

- **kvmtool binary**: path to `lkvm` or `lkvm-static` *inside the guest*
  (i.e. the path as seen from the QEMU host shell). The binary must be a
  statically linked build for the guest architecture. If not available,
  it can be cross-compiled from a kvmtool git repository — see the
  "Cross-Compiling kvmtool" section. Ask the user for a kvmtool repo
  path if the binary is missing and no pre-built binary is available.
- **guest kernel image**: path to the kernel image *inside the guest*.
  Typically the same kernel as the host, shared via virtio-9p.

Both have defaults for the standard buildroot environment (see below).

## kvmtool Invocation

kvmtool is launched from the QEMU host shell. It runs in the foreground
of the host console session — the guest console output appears on the same
terminal, interleaved with the host shell. The guest shell prompt (`/ #`)
signals that the guest is ready.

Minimal kvmtool command (no VFIO, no extra devices):

```bash
lkvm-static run \
    -m 256 \
    -c 2 \
    -p "console=ttyS0 earlycon" \
    -k /path/to/guest/Image \
    --debug
```

Key options:
- `-m <MB>` — guest RAM in megabytes (default: 256)
- `-c <N>` — guest vCPU count (default: 2)
- `-p "<cmdline>"` — guest kernel command line
- `-k <image>` — guest kernel image path
- `--debug` — enables virtio-net and other devices; required for a
  functional guest environment

**No rootfs needed**: when no disk, rootfs, or initrd is specified,
kvmtool automatically creates a minimal generated rootfs in `~/.kvm/`
and mounts it via 9p as `/`. The host's `/` is also shared into the
guest at `/host`.

**Guest kernel cmdline**: kvmtool injects its own rootfs parameters.
The `-p` argument is appended to those. Minimal useful cmdline:
`"console=ttyS0 earlycon"`. Add `ignore_loglevel debug` to see all
dmesg output.

**Guest prompt**: `/ #` (busybox shell from the generated rootfs).

**Guest shutdown**: `poweroff -f` — plain `poweroff` hangs waiting for
a clean shutdown that does not complete under kvmtool.

## Standard Buildroot Environment

In the standard test environment the kvmtool binary and guest kernel are
available inside the QEMU guest via a virtio-9p share:

```
Host path (outside QEMU):  ~/opt/buildroot/share64/
Guest path (inside QEMU):  /share/   (mounted via virtio-9p, tag=p9)
```

The QEMU command must include the 9p share to make these available:

```python
cfg['extra_args'] = [
    '-fsdev local,id=p9,path=/home/USER/opt/buildroot/share64,'
    'security_model=mapped-xattr',
    '-device virtio-9p-device,fsdev=p9,mount_tag=p9',
]
```

With the share mounted, inside the QEMU guest:
- kvmtool binary: `/share/bin/lkvm-static`
- guest kernel:   `/share/runqemu/Image`  (copied there by runqemu-riscv
                   before boot; or copy it manually if not using runqemu)

If the 9p share is not available, copy the kvmtool binary and kernel
image into the rootfs image before booting, or use a different delivery
mechanism.

**`lkvm-static` is a binary that must be provided** — it is a statically
linked RISC-V 64-bit kvmtool build and cannot be generated by this agent.
See the "Cross-Compiling kvmtool" section below for build instructions.
The VFIO helper scripts (`runkvm`, `runkvm-n`, `e1000e-unbind`) are only
needed for device passthrough testing and are not required here.

For a plain guest boot test (no VFIO), invoke `lkvm-static` directly
without any helper script:

```bash
lkvm-static run \
    -m 256 \
    -c 2 \
    -p "console=ttyS0 earlycon" \
    -k /share/runqemu/Image \
    --debug
```

This is equivalent to what `runkvm` does, minus the VFIO bind steps.

## 9p Share Mount

The 9p share is not auto-mounted. Mount it from the host shell after boot:

```bash
mkdir -p /share
mount -t 9p -o trans=virtio,version=9p2000.L,cache=loose p9 /share
```

Or add `p9 /share 9p trans=virtio,version=9p2000.L,cache=loose 0 0` to
`/etc/fstab` in the rootfs. In the standard buildroot image the share is
auto-mounted at boot via an init script — verify with `ls /share/bin/`.

## pexpect Session Structure

The guest runs in the foreground of the host console pexpect session.
After launching kvmtool, wait for `/ #` on the same `child` object:

```python
GUEST_PROMPT = r'/ #'
HOST_PROMPT  = r'#\s*$'

# Launch guest (foreground — blocks until guest exits)
child.sendline('lkvm-static run -m 256 -c 2 '
               '-p "console=ttyS0 earlycon ignore_loglevel debug" '
               '-k /share/runqemu/Image --debug')

# Wait for guest shell
idx = child.expect([GUEST_PROMPT, pexpect.TIMEOUT, pexpect.EOF],
                   timeout=120)
if idx != 0:
    raise RuntimeError('Guest failed to boot')

# Guest is now running — send commands to the guest shell
child.sendline('dmesg -n 1')
child.expect(GUEST_PROMPT, timeout=10)

# ... run checks ...

# Shut down guest
child.sendline('poweroff -f')
child.expect(HOST_PROMPT, timeout=60)   # host prompt returns after guest exits
```

After `poweroff -f` the guest exits and kvmtool returns, restoring the
host shell prompt. The same `child` object is then back at `HOST_PROMPT`.

After the guest shuts down, re-run the host dmesg health checks before
powering off the host. KVM may log errors (e.g. from vCPU teardown or
IOMMU domain cleanup) that only appear after the guest exits. Pass the
same `dmesg_checks` list plus a check for KVM-specific errors:

## Guest dmesg Health Checks

Run the same checks as the host, adapted for the guest context:

```python
def check_guest_health(child, cfg=None):
    """
    Run dmesg health checks inside the kvmtool guest.
    child is at GUEST_PROMPT. Returns (passed, results).
    """
    results = []
    passed = True
    cfg = cfg or {}
    prompt = r'/ #'

    def run(cmd, timeout=15):
        child.sendline(cmd)
        child.expect(prompt, timeout=timeout)
        lines = [l for l in child.before.splitlines()
                 if l.strip() and cmd not in l]
        return '\n'.join(lines)

    # Kernel version
    out = run('uname -a')
    results.append(f'Guest kernel: {out.strip() or "(unknown)"}')

    # BUG / Oops / panic
    out = run(r'dmesg | grep -E "BUG:|Oops:|Kernel panic"')
    bugs = [l for l in out.splitlines() if l.strip()]
    if bugs:
        results.append(f'FAIL: guest BUG/Oops/panic ({len(bugs)} lines):')
        for b in bugs[:5]: results.append(f'  {b.strip()}')
        passed = False
    else:
        results.append('PASS: no guest BUG/Oops/panic')

    # Call traces
    out = run('dmesg | grep -c "Call Trace"')
    n = out.strip().splitlines()[-1].strip() if out.strip() else '0'
    if n.isdigit() and int(n) > 0:
        results.append(f'FAIL: {n} call trace(s) in guest dmesg')
        passed = False
    else:
        results.append('PASS: no guest call traces')

    # Stack frames (RISC-V WARN() emits [<addr>] lines without "Call Trace:" header)
    out = run(r'dmesg | grep -cE "\[<ffffffff"')
    n = out.strip().splitlines()[-1].strip() if out.strip() else '0'
    if n.isdigit() and int(n) > 0:
        results.append(f'FAIL: {n} stack frame line(s) in guest dmesg')
        passed = False
    else:
        results.append('PASS: no guest stack frames')

    # Driver errors and probe failures
    out = run(r'dmesg | grep -cE "error -E[A-Z]+:|probe with driver .* failed"')
    n = out.strip().splitlines()[-1].strip() if out.strip() else '0'
    if n.isdigit() and int(n) > 0:
        results.append(f'FAIL: {n} driver error/probe failure line(s) in guest dmesg')
        passed = False
    else:
        results.append('PASS: no guest driver errors or probe failures')

    # WARNINGs
    if not cfg.get('skip_warning_check'):
        out = run('dmesg | grep -c "WARNING:"')
        n = out.strip().splitlines()[-1].strip() if out.strip() else '0'
        if n.isdigit() and int(n) > 0:
            results.append(f'FAIL: {n} WARNING(s) in guest dmesg')
            passed = False
        else:
            results.append('PASS: no guest WARNINGs')


    # Broad error/warning/failure scan with false-positive filtering
    DMESG_FP = [
        'EXT4-fs',       # unchecked fs warning
        'SIOCGIFFLAGS',  # net interface not up yet
    ]
    out = run(r'dmesg | grep -iE "\\berror\\b|\\bwarn(ing)?\\b|\\bfail(ed)?\\b"')
    broad_hits = [l.strip() for l in out.splitlines()
                  if l.strip() and 'grep' not in l
                  and not any(fp in l for fp in DMESG_FP)]
    if broad_hits:
        results.append(f'FAIL: {label} {len(broad_hits)} unexpected error/warn/fail line(s):')
        for b in broad_hits[:10]: results.append(f'  {b}')
        passed = False
    else:
        results.append(f'PASS: {label} no unexpected errors/warnings/failures in dmesg')

    # Caller-specified guest dmesg checks
    for label, pattern, must_match in cfg.get('guest_dmesg_checks', []):
        out = run(f'dmesg | grep -c "{pattern}"')
        n = out.strip().splitlines()[-1].strip() if out.strip() else '0'
        found = n.isdigit() and int(n) > 0
        if must_match and not found:
            results.append(f'FAIL: expected guest "{label}" not in dmesg')
            passed = False
        elif not must_match and found:
            results.append(f'FAIL: unexpected guest "{label}" found in dmesg')
            passed = False
        else:
            results.append(f'PASS: guest dmesg check "{label}"')

    return passed, results
```

**Expected guest dmesg patterns** for a healthy kvmtool guest on RISC-V
with AIA (informational — add to `guest_dmesg_checks` as needed):

```python
cfg['guest_dmesg_checks'] = [
    ('IMSIC present',    r'riscv-imsic.*per-CPU IDs', True),
    ('APLIC forwarding', r'aplic.*interrupts forwarded to MSI', True),
    # KVM nested not expected in a plain guest:
    # ('KVM not available', r'kvm.*hypervisor extension not available', True),
]
```

Note: `kvm [1]: hypervisor extension not available` in the guest dmesg is
**expected and correct** — the guest is a KVM VM and does not itself run
KVM (no nested virtualisation). Do not flag this as an error.

## Complete Test Script Template

```python
#!/usr/bin/env python3
"""
QEMU + KVM guest boot health test.
Boots the QEMU host, checks host dmesg, boots a kvmtool guest,
checks guest dmesg, shuts down guest then host.
"""
import pexpect, sys, os, re, shlex, time

RESULTS_LOG  = '/tmp/kvm_boot_test.log'
HOST_PROMPT  = r'#\s*$'
GUEST_PROMPT = r'/ #'
BOOT_TIMEOUT = 180

def log(msg):
    print(msg, flush=True)
    with open(RESULTS_LOG, 'a') as f:
        f.write(msg + '\n')

# ── Configuration ────────────────────────────────────────────────────────────
cfg = {
    # Host QEMU config (same as qemu-testing.md)
    'qemu_bin':      '/path/to/qemu-system-<arch>',
    'kernel':        '/path/to/kernel/Image',
    'rootfs':        '/path/to/rootfs.ext2',
    'machine':       'virt',
    'machine_extra': '',
    'cpu':           'max',
    'smp':           4,
    'mem':           '2G',
    'cmdline':       'root=/dev/vda console=ttyS0 earlycon ignore_loglevel debug',
    'ssh_port':      0,
    'boot_timeout':  BOOT_TIMEOUT,
    'console_log':   '/tmp/kvm_boot_console.log',
    'stderr_log':    '/tmp/kvm_boot_stderr.log',
    'extra_args':    [],   # add 9p share here if needed
    'dmesg_checks':  [],   # host dmesg checks

    # Guest kvmtool config
    'lkvm_bin':      'lkvm-static',   # path inside the QEMU guest
    'guest_kernel':  '/share/runqemu/Image',  # path inside the QEMU guest
    'guest_mem':     256,   # MB
    'guest_cpus':    2,
    'guest_cmdline': 'console=ttyS0 earlycon ignore_loglevel debug',
    'guest_timeout': 120,   # seconds to wait for guest shell prompt
    'guest_dmesg_checks': [],  # guest dmesg checks
    'skip_warning_check': False,
}
# ─────────────────────────────────────────────────────────────────────────────

def build_qemu_cmd(cfg):
    machine = cfg['machine'] + cfg.get('machine_extra', '')
    cmd = [
        cfg['qemu_bin'], '-nographic',
        '-machine', machine,
        '-cpu', cfg['cpu'],
        '-smp', str(cfg['smp']),
        '-m', cfg['mem'],
        '-kernel', cfg['kernel'],
        '-append', cfg['cmdline'],
        '-drive', f"file={cfg['rootfs']},id=hd0,format=raw,if=none",
        '-device', 'virtio-blk-device,drive=hd0',
    ]
    if cfg.get('ssh_port'):
        cmd += [
            '-device', 'virtio-net-device,netdev=eth0',
            '-netdev', f"user,id=eth0,hostfwd=tcp::{cfg['ssh_port']}-:22",
        ]
    for arg in cfg.get('extra_args', []):
        cmd += shlex.split(arg) if isinstance(arg, str) else list(arg)
    return cmd

def check_dmesg_health(child, prompt, label, cfg, checks_key='dmesg_checks'):
    """Generic dmesg health check. Returns (passed, results)."""
    results = []
    passed = True

    def run(cmd, timeout=15):
        child.sendline(cmd)
        child.expect(prompt, timeout=timeout)
        lines = [l for l in child.before.splitlines()
                 if l.strip() and cmd not in l]
        return '\n'.join(lines)

    out = run('uname -a')
    results.append(f'{label} kernel: {out.strip() or "(unknown)"}')

    out = run(r'dmesg | grep -E "BUG:|Oops:|Kernel panic"')
    bugs = [l for l in out.splitlines() if l.strip()]
    if bugs:
        results.append(f'FAIL: {label} BUG/Oops/panic ({len(bugs)} lines):')
        for b in bugs[:5]: results.append(f'  {b.strip()}')
        passed = False
    else:
        results.append(f'PASS: {label} no BUG/Oops/panic')

    out = run('dmesg | grep -c "Call Trace"')
    n = out.strip().splitlines()[-1].strip() if out.strip() else '0'
    if n.isdigit() and int(n) > 0:
        results.append(f'FAIL: {label} {n} call trace(s)')
        passed = False
    else:
        results.append(f'PASS: {label} no call traces')

    # Stack frames (RISC-V WARN() emits [<addr>] lines without "Call Trace:" header)
    out = run(r'dmesg | grep -cE "\[<ffffffff"')
    n = out.strip().splitlines()[-1].strip() if out.strip() else '0'
    if n.isdigit() and int(n) > 0:
        results.append(f'FAIL: {label} {n} stack frame line(s)')
        passed = False
    else:
        results.append(f'PASS: {label} no stack frames')

    # Driver errors and probe failures
    out = run(r'dmesg | grep -cE "error -E[A-Z]+:|probe with driver .* failed"')
    n = out.strip().splitlines()[-1].strip() if out.strip() else '0'
    if n.isdigit() and int(n) > 0:
        results.append(f'FAIL: {label} {n} driver error/probe failure line(s)')
        passed = False
    else:
        results.append(f'PASS: {label} no driver errors or probe failures')

    if not cfg.get('skip_warning_check'):
        out = run('dmesg | grep -c "WARNING:"')
        n = out.strip().splitlines()[-1].strip() if out.strip() else '0'
        if n.isdigit() and int(n) > 0:
            results.append(f'FAIL: {label} {n} WARNING(s)')
            passed = False
        else:
            results.append(f'PASS: {label} no WARNINGs')

    for chk_label, pattern, must_match in cfg.get(checks_key, []):
        out = run(f'dmesg | grep -c "{pattern}"')
        n = out.strip().splitlines()[-1].strip() if out.strip() else '0'
        found = n.isdigit() and int(n) > 0
        if must_match and not found:
            results.append(f'FAIL: {label} expected "{chk_label}" not in dmesg')
            passed = False
        elif not must_match and found:
            results.append(f'FAIL: {label} unexpected "{chk_label}" in dmesg')
            passed = False
        else:
            results.append(f'PASS: {label} dmesg check "{chk_label}"')

    return passed, results

def main():
    open(RESULTS_LOG, 'w').close()
    log('=== QEMU + KVM Guest Boot Health Test ===')
    log(f'QEMU:         {cfg["qemu_bin"]}')
    log(f'Host kernel:  {cfg["kernel"]}')
    log(f'Rootfs:       {cfg["rootfs"]}')
    log(f'kvmtool:      {cfg["lkvm_bin"]} (inside guest)')
    log(f'Guest kernel: {cfg["guest_kernel"]} (inside guest)')

    cmd = build_qemu_cmd(cfg)
    qemu_str = ' '.join(shlex.quote(a) for a in cmd)

    child = pexpect.spawn(
        '/bin/bash', ['-c', f'{qemu_str} 2>{cfg["stderr_log"]}'],
        encoding='utf-8',
        logfile=open(cfg['console_log'], 'w'),
        timeout=cfg['boot_timeout'],
        maxread=65536,
        searchwindowsize=4096,
    )

    host_passed = guest_passed = False
    try:
        # ── Boot host ────────────────────────────────────────────────
        idx = child.expect(
            [r'buildroot login:', HOST_PROMPT, r'\$\s*$', pexpect.TIMEOUT],
            timeout=cfg['boot_timeout'],
        )
        if idx == 3:
            log('FAIL: timed out waiting for host login')
            return 1
        if idx == 0:
            child.sendline('root')
            child.expect(HOST_PROMPT, timeout=30)
        log('Host shell ready')

        child.sendline('dmesg -n 1')
        child.expect(HOST_PROMPT, timeout=10)

        host_passed, host_results = check_dmesg_health(
            child, HOST_PROMPT, 'Host', cfg, 'dmesg_checks')
        log('\n--- Host dmesg checks ---')
        for r in host_results: log(r)

        # ── Boot guest ───────────────────────────────────────────────
        log('\n--- Booting KVM guest ---')
        lkvm_cmd = (
            f'{cfg["lkvm_bin"]} run '
            f'-m {cfg["guest_mem"]} '
            f'-c {cfg["guest_cpus"]} '
            f'-p "{cfg["guest_cmdline"]}" '
            f'-k {cfg["guest_kernel"]} '
            f'--debug'
        )
        child.sendline(lkvm_cmd)
        idx = child.expect(
            [GUEST_PROMPT, pexpect.TIMEOUT, pexpect.EOF],
            timeout=cfg['guest_timeout'],
        )
        if idx != 0:
            log('FAIL: guest did not reach shell prompt')
            return 1
        log('Guest shell ready')

        child.sendline('dmesg -n 1')
        child.expect(GUEST_PROMPT, timeout=10)

        guest_passed, guest_results = check_dmesg_health(
            child, GUEST_PROMPT, 'Guest', cfg, 'guest_dmesg_checks')
        log('\n--- Guest dmesg checks ---')
        for r in guest_results: log(r)

        # ── Shutdown guest ───────────────────────────────────────────
        log('\n--- Shutting down guest ---')
        child.sendline('poweroff -f')
        child.expect(HOST_PROMPT, timeout=60)
        log('Guest shut down')

        # ── Post-guest host check ────────────────────────────────────
        log('\n--- Post-guest host dmesg checks ---')
        child.sendline('dmesg -n 1')
        child.expect(HOST_PROMPT, timeout=10)
        post_passed, post_results = check_dmesg_health(
            child, HOST_PROMPT, 'Host(post)', cfg, 'dmesg_checks')
        for r in post_results: log(r)
        host_passed = host_passed and post_passed

        # ── Shutdown host ────────────────────────────────────────────
        child.sendline('poweroff')
        child.expect(pexpect.EOF, timeout=60)
        log('Host shut down')

    except pexpect.TIMEOUT:
        log('FAIL: unexpected timeout')
        host_passed = guest_passed = False
    finally:
        try: child.close()
        except Exception: pass

    overall = host_passed and guest_passed
    log(f'\nHost:  {"PASS" if host_passed  else "FAIL"}')
    log(f'Guest: {"PASS" if guest_passed else "FAIL"}')
    log(f'Overall: {"PASS" if overall else "FAIL"}')
    log(f'Console log: {cfg["console_log"]}')
    log(f'QEMU stderr: {cfg["stderr_log"]}')
    return 0 if overall else 1

if __name__ == '__main__':
    sys.exit(main())
```

## Cross-Compiling kvmtool

When the host machine architecture differs from the guest (e.g. building a
RISC-V `lkvm-static` on an x86_64 host), kvmtool must be cross-compiled.
kvmtool requires libfdt; the Linux kernel source tree provides it under
`scripts/dtc/libfdt/` and is the preferred source to avoid version mismatches.

### Prerequisites

- **Cross-compiler** for the target architecture. Check it is installed:
  ```bash
  riscv64-linux-gnu-gcc --version   # RISC-V 64-bit
  ```
  If missing, install it (Ubuntu/Debian):
  ```bash
  sudo apt-get install gcc-riscv64-linux-gnu   # RISC-V 64-bit
  # sudo apt-get install gcc-aarch64-linux-gnu  # AArch64
  ```
- **kvmtool source tree** — look for it at common locations
  (`~/code/github/kvmtool`, `~/kvmtool`, `./kvmtool`) or clone:
  ```bash
  git clone https://git.kernel.org/pub/scm/linux/kernel/git/will/kvmtool.git
  ```
- **Linux kernel source tree** (for libfdt at `scripts/dtc/libfdt/`)

### Step 1 — Build libfdt for the target architecture

The kernel's `scripts/dtc/libfdt/` contains the libfdt C sources. Build a
static archive for the target using the cross-compiler:

```bash
LIBFDT_DIR=/path/to/linux/scripts/dtc/libfdt
CROSS=riscv64-linux-gnu-   # adjust for target arch

cd "$LIBFDT_DIR"
for f in fdt.c fdt_ro.c fdt_wip.c fdt_sw.c fdt_rw.c fdt_strerror.c \
         fdt_empty_tree.c fdt_addresses.c fdt_overlay.c; do
    ${CROSS}gcc -c -O2 -I"$LIBFDT_DIR" "$f" -o "${f%.c}.o"
done
${CROSS}ar rcs libfdt.a fdt.o fdt_ro.o fdt_wip.o fdt_sw.o fdt_rw.o \
    fdt_strerror.o fdt_empty_tree.o fdt_addresses.o fdt_overlay.o
```

If the kernel tree already contains a pre-built archive for the target
(e.g. `libfdt-riscv64.a`), it can be used directly — copy or symlink it
to `libfdt.a` in the same directory:

```bash
cp "$LIBFDT_DIR/libfdt-riscv64.a" "$LIBFDT_DIR/libfdt.a"
```

### Step 2 — Build lkvm-static

```bash
cd /path/to/kvmtool

make ARCH=riscv \
     CROSS_COMPILE=riscv64-linux-gnu- \
     LDFLAGS=-static \
     LIBFDT_DIR=/path/to/linux/scripts/dtc/libfdt \
     lkvm-static \
     -j$(nproc)
```

`ARCH` values by target:

| Target       | ARCH value | CROSS_COMPILE prefix        |
|--------------|------------|-----------------------------|
| RISC-V 64    | `riscv`    | `riscv64-linux-gnu-`        |
| AArch64      | `arm64`    | `aarch64-linux-gnu-`        |
| x86-64       | `x86`      | (native, omit CROSS_COMPILE)|
| 32-bit ARM   | `arm`      | `arm-linux-gnueabihf-`      |

`LDFLAGS=-static` produces a statically linked binary that runs without
shared libraries in the guest rootfs.

### Step 3 — Verify AIA support (RISC-V)

For RISC-V irqbypass testing, the binary must have been compiled with AIA
support. Verify:

```bash
strings lkvm-static | grep disable-ssaia
```

Expected output: `disable-ssaia` — this option is only present when the
binary was compiled with AIA support (`riscv/aia.c` included). If absent,
the binary was built without AIA and will use PLIC instead of IMSIC,
preventing MSI setup and irqbypass activation.

### Step 4 — Install into the share directory

```bash
cp lkvm-static /path/to/share64/bin/lkvm-static
chmod +x /path/to/share64/bin/lkvm-static
```

### Common build errors

- **`No libfdt found`**: `LIBFDT_DIR` not set, or `libfdt.a` not present
  in that directory. Build libfdt first (Step 1).
- **`LIBFDT_DIR not found`**: the path passed to `LIBFDT_DIR` does not
  exist. Use an absolute path.
- **Linker errors about missing symbols**: the libfdt.a was built for the
  wrong architecture. Rebuild it with the correct `CROSS_COMPILE` prefix.
- **`Exec format error` when running in guest**: the binary was built for
  the wrong target architecture. Check `file lkvm-static` — it must match
  the guest architecture (e.g. `ELF 64-bit LSB executable, UCB RISC-V`).


## Updating Test Scripts

**Always follow this process when modifying test behaviour:**

1. **Delete** the existing test script(s) — never patch them directly.
   The scripts are generated artifacts; patching them creates drift from
   the agent templates and makes future regeneration unreliable.
   ```bash
   rm boot_test.py kvm_boot_test.py   # or whichever scripts are affected
   ```

2. **Update the agent** (`qemu-testing.md` and/or `qemu-testing-kvm.md`)
   with the correct logic — fix the template `check_boot_health` /
   `check_dmesg_health` function, the cfg defaults, or the dmesg check
   lists as needed.

3. **Regenerate the scripts** by following the Task section below,
   filling in the cfg dict from the environment.

This ensures the agent templates and the running scripts are always in
sync. Never accumulate hand-patches in the scripts.

## Task

1. Read the test request. Determine the paths for `qemu_bin`, `kernel`,
   `rootfs`, `lkvm_bin`, and `guest_kernel`. Use the standard buildroot
   defaults if the environment matches (9p share at `/share`, kvmtool at
   `/share/bin/lkvm-static`, guest kernel at `/share/runqemu/Image`).
   Check that `lkvm-static` (or the specified `lkvm_bin`) exists at the
   expected location on the host machine (i.e. in the share directory).
   If it is missing:
   a. Look for a kvmtool git repository on the host (common locations:

   b. If not found, ask the user: "lkvm-static not found at <path>.
      Please provide a path to a kvmtool git repository to build it,

   mount command after host login.
3. Write the test script to the requested path (default: `./kvm_boot_test.py`).
4. Run it: `python3 ./kvm_boot_test.py`
5. Report the result.
